## Decision

A lineage whose child node claims authority that its parent did not hold is denied. Denial is **non-amplification denial**: `authorize()` raises `AuthorityAmplification` for the offending node.

## What was implemented (verified from the code and commits)

- Commit `ea91bf2` changed `NodeBody.authority` to an opaque `frozenset[str]` of capability strings, compared by equality only, with no wildcard or hierarchy semantics, and replaced `delegation_rights` with a boolean `can_delegate`. The authority set is sorted on encode for deterministic canonical CBOR.
- The enforcement of the rule in `authorize()` landed in commit `b327383` ("Enforce authority attenuation in authorize()"), one commit after `ea91bf2`. The rule is: the parent's `can_delegate` is true and the child's authority is a subset of or equal to the parent's authority.

## Known divergence, handled in DR-1

The Spec §3 and §4 name `delegation_rights` as a map and `audience` as an array. The `ea91bf2` representation (boolean `can_delegate`, string audience) diverges from them. DR-1 divergences D15 and D16 record the supervisor's rulings to conform to the Spec. DR-1 does not revoke the non-amplification rule; it keeps it.
