# DR-0002: Protocol-owned RFC 8949 deterministic encoder (D20)

| field | value |
|---|---|
| id | DR-0002 |
| divergence | D20 in `docs/design-revision-1.md` section 3 |
| status | supervisor ruling relayed (escalation under DR-1 ruling 23); recorded with the implementation |
| disposition | conform. The frozen Spec and Design are not amended |

## Finding

Frozen Spec §4 requires RFC 8949 core deterministic encoding. `cbor2.dumps(..., canonical=True)` (cbor2 6.1.4 in `.venv`) orders map keys length-first, the RFC 7049 rule. Reproduced: `{"a": 1, 1000: 2}` encodes as `a2 6161 01 1903e8 02`; RFC 8949 section 4.2.1 requires `a2 1903e8 02 6161 01`, because `19 03 e8` sorts before `61 61` bytewise.

## Decision

Implement a protocol-owned deterministic encoder in `src/lineage_revocation/canonical.py` and use it for every protocol canonicalization path. It must:

1. encode recursively;
2. sort every map's keys by the bytewise lexicographic order of each key's complete encoding (RFC 8949 section 4.2.1);
3. use definite lengths only;
4. use shortest-form integer arguments;
5. forbid floating-point values;
6. reject unsupported types;
7. permit no tag except COSE_Sign1 tag 18;
8. give output independent of dictionary insertion order.

The encoder accepts integer, text and byte-string map keys, because COSE maps use integer labels. Schema validators still reject unexpected key types in protocol bodies.

**Domain restriction is input validation; canonical correctness comes from the encoder.**

## Consequences

- Over the current protocol objects the two orderings coincide, so existing bytes, node ids and signatures are unchanged. A differential test against cbor2 demonstrates this. It is a compatibility check, not the conformance oracle; the RFC 8949 regression and property tests are.
- The verifier's decode, re-encode and byte-compare check uses this encoder (`decode_strict`).
- cbor2 remains in use for decoding only.
- Test helpers that craft deliberately malformed wire input (wrong or nested tags) use cbor2 directly, because the protocol encoder refuses to produce them.
- Statement and artifact wire objects are parsed with `decode_strict`, so a statement whose outer envelope or body is not in deterministic form is wire-malformed. `decode_strict` sees the node envelopes embedded in a statement only as opaque byte strings, so the statement parser additionally requires the received payload to equal the canonical reconstruction of its content (DR-0003 section 4). Both are artifact-integrity defects under DR-0003, not per-statement semantic failures. A tagged envelope that is not a four-element array cannot be re-encoded by the encoder, so the strict decoder refuses it first (DR-0003 section 3).
- **Nesting limit (review finding B3).** The encoder refuses containers nested deeper than `MAX_NESTING_DEPTH` (32; arrays, maps and the COSE tag each count as a level; protocol objects nest about five levels). The strict decoder accepts input up to cbor2's own limit (400), and re-encoding that with an unbounded recursive encoder could exhaust the Python stack, so an unsigned artifact of 399 nested arrays raised an untyped `RecursionError` from a caller already about 200 frames deep, before authentication, bypassing the unavailable-status policy. The limit makes the outcome deterministic and independent of the caller's stack: deep input is a `CanonicalEncodingError`, which the verifier treats as a malformed artifact (S4, `ARTIFACT_MALFORMED`) or, inside an authenticated artifact, a wire-malformed statement (`ARTIFACT_INTEGRITY`). As defense in depth, a `RecursionError` raised while encoding is converted to `CanonicalEncodingError`, so a within-limit value meeting an almost exhausted caller stack fails closed with a typed error instead of leaking.
